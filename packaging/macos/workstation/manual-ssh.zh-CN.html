Mac 工作机手动 SSH 原型

本页记录早期手动接入方式。局域网工作台在 Windows Cage 内批准配对，源码和 Mac 移植进度见工作机说明。

Windows 上已有的 Cage Linux 客机运行已登录的 Claude Code。Mac 上的 Paseo 显示会话，cc-remote 在 Mac 项目中读写文件、执行 shell 命令，并把结果送回同一会话。

本次 Windows 同机验收通过。Mac 适配器已交叉编译并检查 Mach-O 架构与代码签名的逐页哈希。它们是本地开发构建，使用 ad-hoc 签名。macOS 真机启动和局域网会话仍待验证。

生成本次配对参数

填写参数后可以复制对应步骤。页面只在当前浏览器中生成命令。

1 · 在 Mac 生成 SSH 公钥

在连接同一局域网的 Mac 上执行。已有这对密钥时可直接查看公钥。将输出的一行公钥交给 Windows 端，私钥留在 Mac。

mkdir -p "$HOME/.ssh"
if [ ! -e "$HOME/.ssh/cage-lan" ] && [ ! -e "$HOME/.ssh/cage-lan.pub" ]; then
  ssh-keygen -t ed25519 -f "$HOME/.ssh/cage-lan" -C cage-mac
fi
cat "$HOME/.ssh/cage-lan.pub"

请同时记下 Mac 在这张网络上的 IPv4 地址。Windows 的防火墙只向这个来源放行。

2 · 在 Windows 配对并建立局域网入口

先打开「启动 Cage Host」，确认原客机运行正常。在 Cage 的 Linux 终端运行 id -un，将结果填入上方「Linux 客机用户名」。编辑该用户的 ~/.ssh/authorized_keys，将刚才 Mac 的公钥另起一行追加。保留已有条目，每台工作机使用自己的公钥。

在这台 Windows 的管理员 PowerShell 执行下面的首次配置。入口绑定所填的局域网地址与 TCP 2222，目标端口从当前客机配置中读取。脚本会询问当前 Cage 配置目录下 state\lima\<实例名>\ssh.config 的完整路径。

$ErrorActionPreference = 'Stop'
$lan = 'WINDOWS_LAN_IP'
$mac = 'MAC_LAN_IP'
$interfaces = @(Get-NetIPAddress -AddressFamily IPv4 -IPAddress $lan -ErrorAction Stop | Select-Object -ExpandProperty InterfaceAlias -Unique)
if ($interfaces.Count -ne 1) { throw '请确认 Windows 局域网地址及所在的网络接口。' }
$nic = $interfaces[0]
$rule = 'CageWorkstation-LAN-Mac'
$cfg = (Read-Host '输入当前运行客机的 ssh.config 完整路径').Trim('"')
$ports = @(Select-String -LiteralPath $cfg -Pattern '^\s*Port\s+(\d+)\s*$')
if ($ports.Count -ne 1) { throw '请确认当前实例的 SSH 配置。' }
$guestPort = [int]$ports[0].Matches[0].Groups[1].Value
$null = Get-NetTCPConnection -State Listen -LocalAddress 127.0.0.1 -LocalPort $guestPort
$category = (Get-NetConnectionProfile -InterfaceAlias $nic).NetworkCategory.ToString()
if ($category -eq 'DomainAuthenticated') { $category = 'Domain' }
if (Get-NetFirewallRule -Name $rule -ErrorAction SilentlyContinue) { throw '已有同名规则，请先核对。' }
if (Get-NetTCPConnection -State Listen -LocalPort 2222 -ErrorAction SilentlyContinue) { throw '2222 已在使用。' }
if ((netsh interface portproxy show v4tov4) -match '^\s*\S+\s+2222\s+\S+\s+\d+\s*$') { throw '已有 2222 转发，请先核对。' }
$fw = New-NetFirewallRule -Name $rule -DisplayName 'Cage 工作机 SSH' -Direction Inbound -Action Allow -Protocol TCP -InterfaceAlias $nic -Profile $category -LocalAddress $lan -LocalPort 2222 -RemoteAddress $mac
netsh interface portproxy add v4tov4 listenaddress=$lan listenport=2222 connectaddress=127.0.0.1 connectport=$guestPort
if ($LASTEXITCODE -ne 0) {
    $fw | Remove-NetFirewallRule
    throw '创建转发失败。'
}
Get-NetTCPConnection -State Listen -LocalAddress $lan -LocalPort 2222

这是手动原型。Windows 的局域网地址、Mac 的源地址或客机 SSH 端口发生变化时，应停用旧入口，按新参数重新配置。Cage 启停前也请停用手动转发，避免旧规则指向主机后来复用的端口。

3 · 在 Mac 验证连接到正确的客机

将这一段加入 Mac 的 ~/.ssh/config。如果已存在同名 Host，请更新原条目。

Host cage-lan
    HostName WINDOWS_LAN_IP
    Port 2222
    User CAGE_GUEST_USER
    IdentityFile ~/.ssh/cage-lan
    IdentitiesOnly yes

在 Mac 终端连接。为密钥设置了口令时，先运行 ssh-add "$HOME/.ssh/cage-lan"。首次连接前，在 Cage 的 Linux 终端运行 ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub。将结果与 Mac 首次连接时显示的 ED25519 指纹核对。

ssh -T cage-lan 'id -un && uname -s && claude --version'

这一步应看到你填入的客机用户名、Linux 和该客机里的 Claude Code 版本。

4 · 在 Mac 安装并打开工作台

从 Paseo v0.17.2 官方发布页安装对应架构的 DMG。Apple 芯片选 arm64，Intel 选 x64。从 Windows 的 ClaudeCage\Release 复制同架构的 Cage-Workstation-Adapter-macOS-…tar.gz 到 Mac 的下载文件夹。

把适配器解压到以下独立目录，执行连接检查。若已安装过这个目录，先确认要更新的版本。适配器会使用 Mac 的 SSH 别名和客机里的登录状态。

mkdir -p "$HOME/.local/lib"
tar -xzf "$HOME/Downloads/Cage-Workstation-Adapter-macOS-MAC_ARCH.tar.gz" -C "$HOME/.local/lib"
"$HOME/.local/lib/cage-workstation/cage-claude" doctor

检查成功会输出客机 Claude 版本和 ok。打开 Mac 的 ~/.paseo/config.json。新配置可以使用以下完整内容。已有配置时，合并 agents.providers.cage-claude，按需要设置 daemon 的本机监听和 relay。先退出再重新打开 Paseo 使配置生效。



在 Paseo 点「新建工作区」，选择 Mac 上的测试目录和 Claude · Cage。可以发送「请在当前目录写一个测试文件，运行 uname -s 和 pwd，并报告结果」。工具授权后，应在 Mac 原目录看到新文件、系统结果 Darwin 和对应的 Mac 路径。





停用入口或撤销这台 Mac 的配对

以下命令用于本指南创建的单个入口和防火墙规则。Windows 地址要填写创建规则时的实际地址。然后在客机 ~/.ssh/authorized_keys 中移除该 Mac 的公钥即可撤销其后续 SSH 登录。


netsh interface portproxy delete v4tov4 listenaddress=WINDOWS_LAN_IP listenport=2222
Remove-NetFirewallRule -Name 'CageWorkstation-LAN-Mac'





构建来源与适用范围

压缩包内的适配器来自 固定版本的 cc-remote，叠加包内的 cc-remote.patch。cage-claude 指定 Mac 的 OpenSSH 和客户端配置，并让此工作机会话排除旧的 Windows 宿主命令工具。Mac 的普通项目操作在 Mac 执行。


这批 macOS 文件采用本地 ad-hoc 签名，未做 Apple Developer ID 公证。从源码构建时，检出上述 cc-remote 提交，应用 Cage 仓库的 packaging/windows/workstation/cc-remote.patch，用 Bun 1.4.5 执行 bun install --frozen-lockfile。Apple 芯片执行 bun run build:darwin-arm64，Intel 执行 bun build src/main.ts --compile --minify --target=bun-darwin-x64 --outfile dist/cc-remote-darwin-x64。将生成的文件命名为 cc-remote，连同本目录的 cage-claude 放入 ~/.local/lib/cage-workstation，两个文件的权限均设为 755。


工作台只在 Mac 本机监听，跨机通道使用局域网内的 SSH。首次发现与自动配对、多工作机重连、归档恢复和双端删除需分别验收。Windows 转发文档 · cc-remote 工作机配置
